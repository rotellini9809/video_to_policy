mjlab – Motor Controller Stage-1 (Commands Sequence)
===================================================

Run sources (tracking policies on W&B):
- supercelebration: fratelligpt-sapienza-universit-di-roma/mjlab/8eolpgjb
- supersad:         fratelligpt-sapienza-universit-di-roma/mjlab/2rd8me48

Your trained Stage-1 run (example):

0) PRE-FLIGHT (do this once per shell / container)
--------------------------------------------------
# Always ensure W&B is ONLINE (avoid offline runs that don't appear on cloud):
cd /app
wandb online || true
unset WANDB_MODE WANDB_DISABLED

# Headless render setting (safe in docker; ok also if you have display):
export MUJOCO_GL=egl

# Optional: show wandb env state
env | grep -i wandb


1) ROLLOUT COLLECTION (build dataset from tracking runs)
-------------------------------------------------------
Purpose:
- Collect rollouts from a tracking policy (W&B run path resolves checkpoint + motion artifact)
- Save shards (.npz) for training Stage-1 motor controller

Task to use for collection:
- Mjlab-Tracking-Flat-Booster-T1_23

Choose dataset root:
DATASET=./data/motor_controller_rollouts/striker_dataset_v1
mkdir -p "$DATASET"

1.1) Collect from supercelebration
uv run collect-rollouts Mjlab-Tracking-Flat-Booster-T1_23 \
  --wandb-run-path fratelligpt-sapienza-universit-di-roma/mjlab/8eolpgjb \
  --num-episodes 200 \
  --num-envs 64 \
  --output-dir "$DATASET"

1.2) Collect from supersad
uv run collect-rollouts Mjlab-Tracking-Flat-Booster-T1_23 \
  --wandb-run-path fratelligpt-sapienza-universit-di-roma/mjlab/2rd8me48 \
  --num-episodes 200 \
  --num-envs 64 \
  --output-dir "$DATASET"

1.3) Dataset sanity check
find "$DATASET" -maxdepth 4 -type f -name "*.npz" | head
find "$DATASET" -maxdepth 4 -type f -name "metadata.json" | head


2) STAGE-1 TRAINING (latent motor model)
----------------------------------------
Purpose:
- Load rollouts, build safe sampling, compute normalization stats
- Train latent model for motor control

Recommended default (NPMP chunk mode):
uv run train-motor-stage1 \
  --data-root "$DATASET" \
  --latent-type npmp \
  --sample-mode chunk \
  --chunk-len 32 \
  --k-future 10 \
  --max-iters 5000 \
  --val-frac 0.1 \
  --seed 0 \
  --run-name striker_npmp_chunk32_k10_seed0 \
  --beta-kl-end 1e-3 \
  --beta-kl-warmup-iters 2000 \
  --log-every 50 \
  --wandb \
  --wandb-project motor_controller_stage1 \
  --wandb-entity fratelligpt-sapienza-universit-di-roma

Dry-run (checks data + stats, no training):
uv run train-motor-stage1 \
  --data-root "$DATASET" \
  --latent-type npmp \
  --sample-mode chunk \
  --chunk-len 32 \
  --k-future 10 \
  --dry-run


3) POST-TRAIN EVAL (no render)
------------------------------
Purpose:
- Evaluate trained Stage-1 in sim without rendering

NOTE:
- eval expects the run to contain: model_best.pt + metadata.json + normalization_stats.npz
- Usually DO NOT override MJLAB_MOTOR_CONTROLLER_TASK_ID unless you know it's compatible

Example:
uv run eval-motor-stage1 \
  --wandb-run-path fratelligpt-sapienza-universit-di-roma/motor_controller_stage1/clqjavzl \
  --num-steps 5000 \
  --num-envs 32 \
  --checkpoint best


4) POST-TRAIN PLAY (render)
---------------------------
Purpose:
- Visualize Stage-1 with rendering
- play-motor-stage1 typically auto-uses "best" (model_best.pt). It may NOT expose --checkpoint.

Example:
export MUJOCO_GL=egl
uv run play-motor-stage1 \
  --wandb-run-path fratelligpt-sapienza-universit-di-roma/motor_controller_stage1/clqjavzl \
  --num-envs 1 \
  --viewer native

If you need to play a specific iteration (e.g., model_4999.pt) and play has no --checkpoint:
- copy/rename that file to model_best.pt inside the run cache folder:
  /app/logs/motor_controller_stage1/wandb_checkpoints/<RUN_ID>/
  cp model_4999.pt model_best.pt


5) COMMON FAILURES (quick fixes)
--------------------------------
A) W&B shows nothing new
- You were in offline mode:
  wandb online
  unset WANDB_MODE WANDB_DISABLED

B) FileNotFoundError: required file 'metadata.json' not found in W&B run
- Ensure the run contains metadata.json (exact name) + normalization_stats.npz
- If needed, copy them into the local cache folder:
  /app/logs/motor_controller_stage1/wandb_checkpoints/<RUN_ID>/

C) Policy obs dim mismatch (env != model)
- You're overriding MJLAB_MOTOR_CONTROLLER_TASK_ID to a task with different obs.
- For Stage-1 eval/play, avoid overrides unless you verified compatibility.

D) play-motor-stage1 “Unrecognized option --checkpoint / --model_XXXX”
- That command may not accept explicit checkpoint selection.
- Use default best, or rename desired model file to model_best.pt.
